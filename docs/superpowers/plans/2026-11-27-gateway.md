# AgentGuard Gateway (Person 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP gateway on `/mcp` that proxies the team's upstream MCP servers and gives every tool call one deterministic decision (allow / deny / ask), logged to `guard.db`.

**Architecture:** `gateway.py` builds a FastMCP 4.x proxy (`create_proxy(config)`) over the upstream servers and adds one `Guard` middleware. `Guard.on_call_tool` loads the policy and registry fresh, reads today's payment total, calls the pure `shared.policy.evaluate`, logs through `shared.store`, then forwards, blocks, or waits for approval. Other processes talk to us only through `guard.db` and the JSON files.

**Tech Stack:** Python 3.11, fastmcp 4.x, SQLite (WAL), pytest.

**Spec:** `README.md` (sections 3, 5, 6, 7.1, 9) plus Person 1's brief (pasted in chat on 2026-11-27, summarized under Global Constraints).

## Global Constraints

- No LLM in the decision path. Never weaken fail-closed: any exception means deny.
- `policy.json` and `registry.json` are re-read on every call. There is no caching.
- Daily total = SUM(amount_usd) over today's (local date) events with category='payment' and outcome IN ('forwarded','approved').
- Between `daily_payment_total()` and `log_event()` there must be **no `await`**. That keeps one asyncio loop atomic, so concurrent payments can't both slip under the limit.
- Wait for approval with `await asyncio.sleep(1)`, never `time.sleep`. Up to 60s.
- Agent messages, verbatim:
  - `Blocked by policy: {reason_for_agent}. Tell the user.`
  - `The owner rejected this action.`
  - `Pending owner approval (id {approval_id}). Tell the user and stop.`
- Upstream keys come from `.env` and are loaded only in the Gateway process. The agent never sees the keys, `policy.json` or `guard.db`.
- **Security:** bind to `127.0.0.1` by default (env `GUARD_HOST`). If `GUARD_TOKEN` is set, every request must send `Authorization: Bearer <token>`. If the host is not loopback and no token is set, refuse to start.
- Contracts (the JSON shapes, the tables, `Decision`) don't change without asking Person 1, who asks the team.
- Work on branch `person1-gateway`, not `main`.

## Review Focus

1. **The client gives up before the 60s approval wait ends** (an MCP client timeout in the Agent SDK). Expected: the agent gets a clean message, not a hung session. The timeout is configurable (`GUARD_APPROVAL_TIMEOUT`), and Task 4 has a manual 30s check.
2. **Registry names don't match the prefixed tool names.** Then every call gets ask and the demo stalls. Expected: a loud warning at startup that lists the unregistered tools. Covered by a Task 5 test.
3. **`policy.json` is missing or half-written during a reload.** Expected: deny with "Policy check failed", and the next call works once the file is whole. Covered by a Task 3 test.
4. **The upstream tool raises after we allowed it.** Expected: outcome `error`, the payment drops out of the daily total, and the agent gets the upstream error. Covered by a Task 2 test.
5. **Two concurrent $99 payments when only one fits under the daily limit.** Expected: exactly one gets allow. Covered by a Task 3 test.
